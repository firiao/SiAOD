# Отчёт по ЛР 1. Анализ временной сложности

## 1. Аналитическая оценка алгоритмов (худший случай)

*   **`array_sum` (Сумма элементов)**  \(O(N)\). 
    *Обоснование:* цикл проходит по массиву ровно один раз, выполняя одну операцию сложения на каждом шаге.
*   **`array_max` (Поиск максимума)**  \(O(N)\). 
    *Обоснование:* алгоритм делает один проход по массиву, сравнивая каждый элемент с текущим максимумом. Количество сравнений равно \(N-1\).
*   **`count_equal_pairs` (Подсчёт пар)**  \(O(N^2)\). 
    *Обоснование:* используются два вложенных цикла. Внешний делает \(N-1\) итераций, внутренний - от \(N-1\) до 1. Сумма арифметической прогрессии дает \(\frac{N(N-1)}{2}\) операций сравнения, что асимптотически равно \(O(N^2)\).
*   **`binary_pow` (Бинарное возведение в степень)** — \(O(\log N)\). 
    *Обоснование:* на каждой итерации цикла `while` степень `n` уменьшается в два раза (`n = n // 2`). Количество итераций равно количеству бит в двоичном представлении числа \(N\), то есть \(\lfloor\log_. (N)\rfloor + 1\).

## 2. Сопоставление теории и замеров (log-log график)

На графике `lab01_loglog.png` (оси логарифмические) степенная зависимость \(t = c \cdot N^k\) превращается в прямую линию с наклоном \(k\).
*   Для `array_sum` и `array_max` наблюдаемый наклон \(\approx 1.0\), что соответствует теоретической оценке \(O(N)\).
*   Для `count_equal_pairs` наблюдаемый наклон \(\approx 2.0\), что подтверждает квадратичную сложность \(O(N^2)\).
*   *Расхождения:* небольшие отклонения от целых чисел (например, 1.05 или 1.98) объясняются накладными расходами интерпретатора Python, кэшем процессора и временем на вызов функций.

## 3. Особенности замера логарифмического алгоритма (`binary_pow`)

*   **Почему не log-log:** В осях log-log логарифмическая функция \(\log(N)\) выглядит как \(\log(\log(N))\) — очень пологая кривая, по которой трудно определить порядок роста. Поэтому для алгоритмов с логарифмической сложностью строят график \(t\) от \(\log_2(N)\) в линейных осях. На таком графике зависимость становится прямой линией (что видно на `lab01_binary_pow.png`).
*   **Почему по модулю (`mod=1000000007`):** Без модуля при возведении \(3^{100000}\) в степени образуется число длиной в десятки тысяч знаков. Python потратит основное время на длинную арифметику (сложение огромных чисел), а не на сам алгоритм. Взятие остатка по модулю ограничивает размер чисел, позволяя измерить чистое время работы алгоритма (количество итераций).
